# ADR-0009: 후기 원문 링크는 **참조**로 — 식별자 저장 + 판매자 미디어만 임베드

- 상태: 승인 (미디어 임베드는 프레이밍 검증 1/2 통과 — 아래 §4)
- 관련: [ADR-0002 소스 편향 1급](0002-source-bias-first-class.md) ·
  [ADR-0003 IG 1층 fixture](0003-ig-businessdiscovery-fixture.md) ·
  [ADR-0007 collected_for 타깃 방침](0007-collected-for-target-policy.md)
- 영향: `sql/schema.sql`(`reviews.source_ref`), `slime_rag/source_links.py`(신규),
  `slime_rag/index.py`, `slime_rag/pipeline.py`, `slime_rag/search.py`,
  `slime_rag/consolidated_view.py`, `slime_rag/layer1.py`,
  `slime_rag/sources/dcinside.py`, UI(제거됨)

## 맥락

사용자 동기는 한 문장이다 — **"people don't fully trust AI summaries yet, so every claim
should be verifiable against its original."** 그래서 성공 기준은 '링크가 있다'가 아니라
**'표시된 근거에서 원문으로 도달 가능하다'** 이다.

그런데 이 repo 의 절대 규칙 중 하나가 **원문 미재배포**(본문·미디어 바이트 미저장)다.
링크와 임베드가 그 규칙과 충돌하는지부터 정해야 한다.

## 결정

### 1. 링크·임베드는 복제가 아니라 **참조** — 무재배포와 충돌하지 않는다

저장하는 것은 **주소**뿐이고, 바이트는 계속 원 저작자의 서버에서 열람자에게 직접 간다.
따라서 다운로드·재호스팅은 **배제**한다 — 원칙 위반이기도 하지만, 실무적으로도
인스타 CDN URL 은 수일 내 서명이 만료돼 죽는다. **`/embed` permalink 형태만이 유효한
이유**가 이것이다: 만료되는 자산 주소가 아니라 안정적인 게시물 주소를 가리킨다.

> ⚠️ **적용범위 사후 한정** — [ADR-0010](0010-market-logo-assets.md): 여기서 말하는 배제 대상은
> **후기 본문·게시물 미디어**(리뷰 대상 저작물)다. 마켓 **본인 프로필 아바타**는 예외로
> 다운로드·재호스팅한다(마켓당 1개·320px·링크백 필수). 프로필 아바타에는 `/p/{shortcode}/embed`
> 같은 안정 주소가 없어 §1 을 문자 그대로 두면 로고가 구성상 불가능하기 때문이다.

### 2. 렌더된 URL(TEXT)이 아니라 **식별자(`source_ref` JSONB)** 를 저장한다

```json
{"platform": "dcinside", "url": "...view/?id=amos&no=201513",
 "thread_no": "201513", "comment_no": "1088714"}
```

- **왜 새 컬럼인가**: `post_id` 로 재구성하는 안(URL·순번을 이미 담고 있다)을 먼저 검토했고
  기각했다. `post_id` 의 댓글 성분은 댓글 id 가 아니라 **런 전체의 `enumerate` 위치**라
  원문 주소로 되돌릴 수 없다. 재구성 안은 결국 새 컬럼으로 수렴한다.
- **왜 URL 이 아니라 식별자인가**: 댓글 앵커 형식이 미확정이라(§3) URL 을 구워두면 앵커
  판단이 바뀔 때 **재수집 없이 복구할 수 없다**. `relevance_meta` 가 문장이 아니라 구조화
  판정을 저장하는 것과 같은 이유다.
- 조각 단위 속성이라 제품별 팬아웃 행 전체에 복제된다. **`relevance_meta` 와 소비 방식이
  다르다**: 저건 행 단위 집계 입력이고 이건 식별자라, 읽는 쪽에서 중복 제거가 필요하다
  (`source_links.evidence_group_key`). 안 하면 한 조각이 제품 수만큼 링크로 도배된다.
- 정책은 순수 모듈 `slime_rag/source_links.py` 한 곳에 모았다 — DB·네트워크·Streamlit
  무의존이라 무비용 CI 가 정책 전체를 게이트한다(`eval/test_source_links.py`). UI 는 렌더만.

**백필 정책**: 기존 색인 행은 `source_ref IS NULL` 로 남는다. `index_gold` 가 존재 `post_id`
를 스킵하므로 `setup(reset=False)` 로는 영원히 안 채워진다. 운영 DB 개념이 없는 포트폴리오라
**UPDATE 마이그레이션은 만들지 않고**, 데모 DB 는 `setup(reset=True)` 재적재로 채운다.
⚠️ 단 `setup()` 이 재생성하는 것은 fixture(1층) + 골드뿐이다 — **라이브 수집분은 git 에 없어
`reset=True` 로 사라진다.** 실수집 행이 들어 있는 DB 를 리셋할지는 그때 사람이 판단한다.

### 3. `layer1` permalink 폴백 **제거** (기존 결정의 재결정)

`seed_kb_products` 는 제품에 `source_permalink` 이 없으면 **그 마켓 첫 게시물의 permalink** 를
주입했다(2026-06-29 결정: "공식 스펙 URL = 게시물 permalink 재사용"). 이를 철회한다.

마켓의 게시물과 제품은 1:1 이 아니다. 게다가 이 분기는 끝 상태 둘(전량 null / 전량 채움)에선
죽어 있고 **입력을 채우는 중간 구간에서만 살아난다** — 살아나는 유일한 순간이 곧 오귀속이
생기는 순간이다. 감시할 게 아니라 없앤다.

- **효과**: `specs.source_permalink` 은 **있으면 무조건 정확**해진다. 미디어 임베드 게이트가
  "null 이냐 아니냐"로 단순해지고, provenance 컬럼(`source_permalink_kind`)은 영구히 불필요해진다.
- **수용한 부작용**: 아직 permalink 를 안 채운 제품은 링크가 **아예 안 뜬다**. 마켓 게시물
  링크로 때우지 않는다 — 틀린 링크는 링크 없음보다 나쁘다.

### 4. 미디어는 **판매자 본인 게시물만**, `/p/{shortcode}/embed` 로

- 임베드 대상은 1층 공식 스펙 카드(=정의상 판매자 게시물)뿐이다. **유저 후기 미디어는 어떤
  경로로도 임베드하지 않는다.**
- **DCInside 는 텍스트 링크 카드로 확정**: 임베드 엔드포인트가 없고, CDN 핫링크는 참조가
  아니라 사실상 재배포라 §1 과 충돌한다.
- ⚠️ **`/p/{shortcode}/embed` 는 문서화되지 않은 엔드포인트다.** 공식 oEmbed **API** 는
  App Review 를 요구한다 — [ADR-0003](0003-ig-businessdiscovery-fixture.md) 과 **같은 벽**이라
  이 데모에선 못 쓴다. 그래서 미문서화 경로를 쓰되, **예고 없이 깨질 수 있음을 명시**한다.

**검증 결과 (2026-08-06)**

| 스텝 | 결과 |
|---|---|
| ① 헤더 — `GET /p/<code>/embed` | **통과**. HTTP 200, `X-Frame-Options` **없음**, CSP 에 `frame-ancestors` **없음** → 서버측 프레이밍 차단 없음 |
| ② 브라우저 — 실제 영상 게시물 포스터+재생 | **미완**. 레포에 실제 IG URL 이 하나도 없다(fixture permalink 전량 null, tranche 2 사용자 입력 대기) |
| 부수 확인 — 없는 shortcode | HTTP 200 + "The link to this photo or video may be broken, or the post may have been removed." **에러 페이지**. 삭제·비공개 게시물이면 카드 안에 이 화면이 뜬다 |

②가 미완이라도 코드는 **fail-closed** 라 위험이 없다: `embed_url()` 이 permalink 없는 스펙에
None 을 돌려주므로, permalink 가 전량 null 인 현재 배포본에서는 임베드가 **하나도 렌더되지
않는다**. tranche 2 로 실제 URL 이 들어오는 순간 켜지고, 그때 ②를 눈으로 확인하면 된다.

**실패 모드(설계로 흡수)**: 고정 height 지정 · 삭제/비공개면 프레임 안에 IG 에러 화면 ·
브라우저(Safari ITP·Firefox ETP·차단 확장)가 서드파티 프레임을 막으면 빈 칸이 되는데
**서버에서 감지 불가**. → iframe 아래 텍스트 링크를 **항상** 유지하고, 빈 칸 가능성과
제3자 쿠키를 캡션으로 고지한다.

## 결과

- 챗 근거와 요약 '근거 원문' 목록에서 원문으로 클릭 도달할 수 있다. 식별자 없는 행은
  **텍스트만** 남는다(깨진 링크 0).
- 근거 목록은 식별자로 중복 제거하고 **렌더된 URL 로 그룹핑**한다. 앵커가 없어 한 스레드의
  글·댓글이 한 줄로 묶이므로 라벨을 "댓글 N건"이라고만 쓰지 않는다 — 그 그룹은 댓글만이
  아니다. **라벨도 귀속 정확성의 일부다.**
- 서포터(홍보성) 후기에도 링크를 준다 — 단 서포터 블록 안에서만. 대가성을 감추지 않는 것과
  원문을 확인하게 해 주는 것은 같은 목표에 복무한다.
- **정직성 캡션**: evidence 는 원문 인용이 아니라 `render_review()` 의 구조화 렌더링이다.
  링크를 다는 순간 사용자는 근거 문구를 원문에서 찾으려 드는데 **못 찾는 게 정상**이므로
  먼저 밝힌다. 이건 장식이 아니라 이 기능의 가장 과소평가된 실패(신뢰 역효과)에 대한 완화다.
- 검색 경로의 `_dense`/`_sparse` 위치 하드코딩(`r[6]`, `r[:6]`)을 명명 인덱스로 교체했다.
  컬럼을 하나 끼워 넣는 것만으로 **예외 없이** BM25 가 파손되던 자리다.

### 정직한 인정 — 이 컬럼이 실제로 산 것

디시 댓글 **점프 앵커는 배송되지 않았다**. 2026-08-06 라이브 확인: 댓글 고유 id 는 확보되지만
(댓글 JSON 의 `no`), 게시물 HTML 에 per-comment 앵커가 **없다** — 댓글은 AJAX 로 클라이언트가
그려서 서버 HTML 에 댓글 id 문자열도 `comment_li`/`#comment` 앵커도 0건이고, 비동기로 삽입된
노드에는 브라우저가 프래그먼트 점프를 다시 걸지 않는다.

가짜 앵커는 붙이지 않는다(수집기가 굽던 `#cmt` 도 `permalink()` 가 **제거**한다 — 그 자리엔
아무것도 없다). 따라서 댓글도 스레드 URL 로 간다.

→ **이 컬럼이 산 것은 배송된 앵커가 아니라, 보존된 `comment_no` 라는 옵션 가치다.** 앵커가
확인되는 날 재수집 없이 켤 수 있다. 산 것을 부풀리지 않는다.

## 대안

- **링크만, 미디어 영구 보류**: diff 는 작지만 얻는 게 diff 크기뿐이다. 임베드 게이트는 이미
  fail-closed 라 추가 리스크가 없어 보류할 이유가 약하다.
- **링크+미디어 한 커밋**: 롤백 입도 문제. 미디어에서 문제가 나면 핵심 가치인 링크까지 되돌아간다.
- **새 컬럼 없이 `(source, post_id)` 에서 재구성**: 스키마 변경 0 이라 매력적이지만 댓글 고유
  id 를 영구히 복구할 수 없다(§2). 사용자가 명시적으로 요구한 'DC 댓글' 항목을 포기하게 된다.
  — 단 §4 의 정직한 인정대로, 앵커가 배송되지 않은 **현재 시점의 화면 동작은 이 안과 같다.**
  갈리는 건 미래의 복구 가능성이다.

> 결정 자체는 유효하고 백엔드 쪽 근거(`consolidated_view` · `source_links`)는 그대로 산다 —
> 사라진 건 그 결정을 렌더하던 화면뿐이다.

> **2026-08-06 주석([ADR-0013](0013-processing-vs-publication.md))**: 아래 '무재배포' 전제가 다시 그어졌다.
> 원문 본문의 **저장·LLM 처리는 이제 허용**이고, 제한은 **표시**에만 걸린다(서버 발췌 + 링크).
> §1 의 결론(링크·임베드는 복제가 아니라 참조)은 **그대로 유효**하다 — 링크는 애초에 복제가 아니다.
