# ADR-0011 — 요약 섹션을 6기준으로 확장 + 단일 검색 페이지로 UI 재편

**상태:** Accepted (2026-08-06, 사용자 결정)

## 맥락
디자인 `Slime Search.dc.html`(Kyobo Design System 토큰 + 슬믈리에 민트 액센트)이 화면 구조를
확정했다. 그 디자인이 요구하는 것과 당시 구현의 격차는 셋이었다.

**① 평가 기준 표가 6기준을 요구한다** — 질감·향·소리·지속력·고객 응대·배송을 소스별(인스타/
아모스갤) + 통합 3열로 보여주는 표. 그런데 `SOURCE_REVIEW_SCHEMA` 는 향·질감·배송 셋뿐이었다
([ADR-0008](0008-drop-value-add-shipping-section.md)에서 배송이 승격된 상태). 결정적인 건
**소리·지속력 재료는 이미 LLM 에 넘어가고 있었다**는 점이다 — `ATTR_FIELDS` 와 `_SALIENT` 에
`sound`/`longevity` 가 있어 evidence 가 프롬프트에 실렸는데, 담을 필드가 없어 pros/cons 로만
샜다. ADR-0008 이 `value` 에 대해 지적한 "표시·필터·순위 중 어디에도 닿지 않는 축"의 정반대
상황 — 재료는 도달했는데 **출구가 없는** 축이었다.

**② 챗 화면이 디자인에 없다.** 기존 앱은 '리뷰 요약' / '챗' 두 탭이었다.

**③ 디자인이 네 블록을 생략했다** — 소스 감성 갭, 향 불일치, 서포터(협찬) 블록, 근거 원문 목록.

## 결정
1. **요약 스키마를 6기준으로 확장.** `CRITERIA` 리스트를 `consolidated_view.py` 에 단일 출처로
   두고, `SOURCE_REVIEW_SCHEMA` 의 required·properties 와 UI 표가 **그 1벌을 공유**한다.
   소스별·통합·서포터 세 프롬프트 모두 동일 규칙(미언급=null, 지어내기 금지).
2. **`shipping_cs` 재료 하나를 `cs`·`shipping` 두 섹션으로 분기.** 물류 사실(발송·도착 속도·포장·
   파손·누락)은 `shipping`, 사람의 응대(문의 답변·교환·환불·사과·태도)는 `cs`.
   **DB·추출 스키마는 무변경** — 분기는 요약(표시) 단계에서만 일어난다.
3. **챗 화면 제거.** `search.answer` 코드는 남기되 UI 진입점을 없앤다.
4. **생략된 네 블록은 당분간 넣지 않는다**(사용자 결정). 아래 '유보' 참조.
5. **UI 를 단일 스크롤 검색 페이지로 재편.** 헤더 검색(마켓·제품 자유 입력) → 히어로 →
   1층 스펙 → 리뷰 요약(3카드 + 6×3 표) → 커뮤니티 리뷰(소스별 패널, 섞지 않음).
   범위 라디오는 삭제하고 **범위를 입력에서 파생**시킨다(제품까지 넣으면 제품 범위).

## 근거
- **Why 1:** 축의 값은 ADR-0008 의 판정 기준 그대로 '표시·필터·순위 중 어디에 닿는가'다.
  소리·지속력은 이제 표에 닿는다. 그리고 재료가 이미 프롬프트 비용을 치르고 있었으므로
  **추가 입력 비용은 0**이고, 늘어나는 건 출력 토큰(섹션 3개분)뿐이다.
- **Why 1 (드리프트 차단):** 기준을 UI 와 스키마 두 곳에 적으면 한쪽만 늘어나는 조용한 드리프트가
  난다 — 스키마에 기준을 더해도 표는 그대로이거나 그 반대. `CRITERIA` 1벌 공유를 테스트로 고정한다
  (`test_criteria_shared_with_backend`).
- **Why 2:** 고객 응대와 배송은 **책임 주체가 다르다** — 지연은 택배사 몫일 수 있어도 무응답은
  판매자 몫이다. 구매 결정에서 둘은 다른 정보다. 반대로 추출 단계에서 가르지 않는 이유는
  한 문장에 섞여 나오는 일이 흔해서다("3일 지연에 문의도 무응답") — 문장을 쪼개는 판단은
  요약 LLM 이 문맥을 갖고 하는 편이 낫고, 그래야 ADR-0005 의 주문 단위 필드 구조도 안 깨진다.
- **Why 5:** 디자인의 헤더가 '마켓(선택) + 제품(선택)' 두 입력이라, 범위는 이미 입력에 들어 있다.
  라디오를 따로 두면 같은 사실을 두 번 묻는 것이 된다.

## 유보 (결정 4의 대가 — 의도적으로 기록)
생략한 네 블록 중 **셋은 문서상 유지 의무가 있던 것**이다. 되돌릴 때 무엇을 되살릴지 남긴다.

| 블록 | 근거 문서 | 백엔드 상태 |
|---|---|---|
| 소스 감성 갭(인스타 net vs 디시 net) | [ADR-0002](0002-source-bias-first-class.md) 소스 편향 1급 | `view["sentiment_gap"]` 그대로 산출됨 |
| 향 불일치(공식향 vs 체감향) | CLAUDE.md 절대 규칙(조인·집계 산출) | `view["scent_divergence"]` 그대로 산출됨 |
| 서포터(협찬) 후기 블록 | 사용자 결정 2026-07-15(소수라도 실내용 요약) | `view["promo_view"]` 그대로 산출됨 |
| 근거 원문 **목록** 섹션 | [ADR-0009](0009-source-links-and-owner-media.md) | `view["sources"]` 그대로 산출됨 |

**넷 다 집계·요약은 계속 돈다 — 빠진 건 표시뿐이다.** 되살리기는 렌더 함수 추가로 끝난다.
원문 링크 자체는 살아 있다: 커뮤니티 리뷰 카드마다 '원문 보기'가 붙는다(목록 섹션만 없음).
서포터 후기는 `review_class='genuine'` 필터로 커뮤니티 패널에서도 빠지므로, 실사용 후기에
협찬분이 섞여 보이는 일은 없다.

## 영향
- `slime_rag/consolidated_view.py` — `CRITERIA`/`CRITERIA_KEYS` 신설, `SOURCE_REVIEW_SCHEMA` 6기준,
  세 프롬프트 갱신(`_SPLIT_NOTE` 공유), `promo_view` 기본 키가 6기준을 따라간다.
- `slime_rag/pipeline.py` — `list_reviews`(커뮤니티 패널용 개별 후기) + `REVIEW_SORTS` 신설.
- UI(제거됨) — 전면 재작성했다가 2026-08-06 통째로 삭제. KDS 토큰 인라인, 챗·사이드바 제거였다.
- 렌더 테스트(제거됨) · [`eval/test_consolidated_sections.py`](../../eval/test_consolidated_sections.py) — 후자만 살아 6기준 계약을 계속 게이트한다.

## 알려진 한계 (구현이 디자인에 못 미치는 지점)
디자인의 리뷰 카드는 작성자·작성일·좋아요/조회/추천 수를 보여주는데, `reviews` 테이블에
그 컬럼이 없다. 수집기(`RawReview.posted_at`·`meta`)는 이미 갖고 있으므로 영속화만 하면 되지만
스키마 마이그레이션 + 재수집이 필요해 이번 범위 밖이다. 그래서:

- **작성일 대신 수집일**(`created_at`)을 쓰고 화면에도 '수집'을 라벨에 남긴다. 정렬도
  '최신순'이 아니라 **'최근 수집순'**이다 — 없는 걸 최신순이라 부르면 거짓말이 된다.
- **좋아요/조회/추천순 정렬은 넣지 않는다.** 대신 데이터가 실재하는 축(정서)으로
  '긍정 먼저 / 부정 먼저'를 제공한다. 컬럼이 생기면 `REVIEW_SORTS` 에 한 줄 추가로 켜진다.
- **카드 본문은 근거 스니펫**(`reviews.evidence`)이지 후기 원문이 아니다. 원문 게재는 무재배포
  원칙(CLAUDE.md 절대 규칙) 위반이라, 디자인의 '캡션이 그대로 들어가요'는 **채택하지 않는다**.
  원문은 링크로만 간다.
- 슬믈리에 로고는 `web/public/brand/` 의 logo·wordmark 가 있으면 이미지, 없으면 텍스트 워드마크로
  degrade 한다([ADR-0010](0010-market-logo-assets.md) 의 모노그램 폴백과 같은 fail-soft 규칙).

> **2026-08-06 주석(ADR-0012)**: 이 ADR 이 언급한 Streamlit UI 파일은 삭제됐다.
> 결정 자체는 유효하고 백엔드 쪽 근거(`consolidated_view` · `source_links`)는 그대로 산다 —
> 사라진 건 그 결정을 렌더하던 화면뿐이다.

> **2026-08-06 주석([ADR-0013](0013-processing-vs-publication.md))**: 아래 '카드 본문은 근거 스니펫'
> 결정은 **뒤집혔다**. 이제 카드는 원문 본문의 **서버 발췌**를 싣는다. 다만 디자인의 '캡션이 그대로
> 들어가요'를 전부 채택한 것은 아니다 — 전문이 아니라 발췌다.
