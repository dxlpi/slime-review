# ADR-0012: Streamlit 프런트엔드 **전면 제거** — 화면은 백지에서 다시 만든다

- 상태: 승인 (2026-08-06, 사용자 판정)
- 관련: [ADR-0011 요약 6기준 + 단일 검색 페이지](0011-six-criteria-summary-and-search-page.md)(이 ADR 이
  그 **구현체**를 폐기한다 — 결정 자체는 유지) ·
  [ADR-0009 원문 링크·판매자 미디어](0009-source-links-and-owner-media.md) ·
  [ADR-0010 마켓 로고](0010-market-logo-assets.md)(둘 다 정책층은 생존)
- 영향: `app/`(삭제), 렌더 테스트(삭제), `requirements.txt`(streamlit 제거),
  `web/public/brand/`(신규 — 브랜드 에셋 보관), `ARCHITECTURE.md`, `README.md`, `CLAUDE.md`,
  `.github/workflows/ci.yml`
- **백엔드 변경 없음**

## 맥락

ADR-0011 의 `Slime Search` 화면은 완성되어 라이브 데이터로 돌았다. 2026-08-06 실행 검증에서
검색 → 히어로 → 1층 스펙 카드 → 리뷰 요약 → 커뮤니티 리뷰까지 예외 없이 렌더됐다(빈짱 /
한글과자한줌, 아모스갤 2건).

**그럼에도 사용자가 결과물을 거부했다.** 판정은 부분 수정이 아니라 전면 폐기였다 — "지우고
처음부터 다시". 화면 품질에 대한 판단은 만든 사람이 아니라 쓰는 사람 몫이므로, 이 ADR 은
그 판단의 타당성을 논하지 않고 **되돌릴 수 있는 형태로 집행**하는 데만 관심이 있다.

Streamlit 자체의 한계도 이 판정에 겹쳐 있었다. 디자인(`Slime Search.dc.html`)은 임의 마크업을
전제하는데, Streamlit 은 위젯 골격을 강제하고 그 위에 CSS 를 덧발라야 한다 — `ui.py` 874줄
가운데 상당량이 `stMarkdownContainer` 의 `margin-bottom:-1rem` 을 되돌리거나 컬럼 비율을
교정하는 **프레임워크와의 싸움**이었다. 같은 디자인을 다시 구현한다면 그 세금은 안 내는 게 맞다.

## 결정

1. **표시 계층을 통째로 삭제한다.** `app/` 전체와 렌더 테스트를 지운다. 부분 리팩터링이 아니다 —
   남겨두면 다음 구현이 그 구조를 답습한다.
2. **백엔드는 한 줄도 건드리지 않는다.** 이게 가능하다는 것 자체가 기존 경계 설계의 검증이다:
   평가 기준(`consolidated_view.CRITERIA`), 링크 정책(`source_links.py`), 로고 게이트
   (`logo_asset`), 데이터 접근(`pipeline.list_*` / `consolidated_for` / `answer`)이 전부 UI 밖에
   있었기 때문에 화면을 버려도 도메인 지식이 같이 죽지 않는다.
3. **브랜드 에셋은 살린다.** 슬믈리에 로고·워드마크는 UI 코드가 아니라 자산이므로
   `web/public/brand/` 로 옮긴다. ADR-0010 의 마켓 로고(`data/market_logos/`, 13개)도 그대로 둔다.
4. **되돌릴 수 있게 집행한다.** 삭제 시점의 작업 트리(미커밋 `ui.py` 포함)를 레포 **바깥**
   `~/Desktop/SlimeReview-frontend-removed-2026-08-06/` 에 통째로 보관한다.
5. **재작성 스택은 이 ADR 에서 정하지 않는다.** 위치만 정한다 — 별도 레포가 아니라 이 레포의
   `web/`. 근거: 새 화면은 `slime_rag` 위에 API 층을 새로 요구하고 그 계약은 매 커밋 같이
   움직인다. 레포를 가르면 커밋·배포·계약 드리프트가 2배가 되는 반면, Render 는 한 레포에서
   서비스별 Root Directory 로 다중 배포를 지원하므로 모노레포가 배포를 막지 않는다.

## 결과

**좋은 것**
- 도메인 자산 손실 0. 6기준·링크·로고·편향 규칙은 전부 백엔드에 남아 CI 게이트를 계속 통과한다
  (`eval/test_source_links.py`, `eval/test_consolidated_sections.py`).
- 다음 구현이 Streamlit 우회 CSS 를 상속하지 않는다.

**나쁜 것 (정직하게)**
- **하드게이트 #1(배포 데모)이 후퇴했다.** 남은 유일한 게이트가 배포였는데, 이제 배포할 화면이
  없다. 재작성이 그 게이트의 선행 조건이 됐다.
- 삭제된 작업은 **git 히스토리에 없다.** `ui.py` 의 미커밋분(+1110/-619)과 로고는 커밋 전
  상태였고, 사용자가 커밋 없는 진행을 택했다. 레포 밖 백업이 유일한 복구 경로이며 이는
  BUILD_LOG 의 생산성 증거로는 약하다 — 하드게이트 #2 가 그만큼 얇아졌다.
- `search.answer` 는 소비자가 없는 채로 남는다(ADR-0011 에서 이미 그랬고, 상태 유지).

## 대안 (기각)

- **점진 개선** — 사용자 판정이 "부분 수정"이 아니었다. 기각.
- **디자인만 갈고 Streamlit 유지** — 위 프레임워크 세금이 그대로 남는다. 기각.
- **별도 레포** — API 계약이 갈라진다(결정 5의 근거). 기각.
- **삭제 전 커밋** — 권고했으나 사용자가 진행을 택했다. 레포 밖 백업으로 대체.
