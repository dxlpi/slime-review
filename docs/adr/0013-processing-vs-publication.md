# ADR-0013: 무재배포 원칙을 **처리 / 공표**로 나눠 다시 긋는다

- 상태: 승인 (2026-08-06, 사용자 판정) — 기존 "원문 미재배포(스니펫만)" 절대 규칙의 **재정의**
- 관련: [ADR-0009 원문 링크·판매자 미디어](0009-source-links-and-owner-media.md)(§1 의 전제를 다시 씀) ·
  [ADR-0010 마켓 로고](0010-market-logo-assets.md)(예외 → 사례로 강등) ·
  [ADR-0011](0011-six-criteria-summary-and-search-page.md)(카드 본문 = 스니펫 결정을 뒤집음)
- 영향: `sql/schema.sql`(본문·메타 컬럼 신설), `slime_rag/index.py`, `slime_rag/pipeline.py`,
  `slime_rag/sources/`, `CLAUDE.md`, `README.md`, `MEMORY.md`, 각 모듈 `CLAUDE.md`

## 맥락

원래 목표가 **요약 생성**뿐이었을 때는 "원문을 저장하지도, 보여주지도 않는다"가 비용 없는
선택이었다. 요약에 필요한 건 구조화 추출 결과지 원문이 아니었기 때문이다. 그래서 규칙이
스키마까지 내려갔다 — `reviews` 에 본문·제목·닉·작성일 컬럼이 **아예 없다**. 가진 건 15자
`evidence` 스니펫과 `attributes` JSONB 뿐이다.

목표가 바뀌었다. 이제 화면은 개별 커뮤니티 리뷰를 카드로 보여주고, 카드마다 원문 링크가
붙는다(ADR-0009). 그러자 기존 규칙이 실제로 막고 있는 게 무엇인지 다시 봐야 했다.

**기존 규칙은 성격이 다른 세 가지를 한 단어로 묶고 있었다.**

| 행위 | 저작권법상 성격 | 기존 규칙 |
|---|---|---|
| 수집·DB 저장 | 복제. 비공개면 노출 없음 | 금지했다 |
| LLM 투입(추출·요약) | 처리. 공표 아님, 산출물은 변형물 | 금지했다 |
| 원문 전문을 화면에 표시 | **공표에 가까움** | 금지했다 |
| 원문 링크 | 복제가 아님 | 애초에 해당 없음 |

위험은 아래로 갈수록 커지는데 규칙은 넷을 똑같이 취급했다. 특히 **LLM 투입을 막을 이유가
없다** — 처리는 공표가 아니고, 요약은 오히려 변형 산출물이라 인용 법리에서 유리한 쪽이다.
규칙이 가장 안전한 행위를 가장 강하게 묶고 있었던 셈이다.

법적 근거 자체는 실재한다(변호사 자문 아님, 일반 정리):
저작권법 **제28조(공표된 저작물의 인용)** 는 "정당한 범위 안에서 공정한 관행에 합치되게"를
요구한다 — 발췌 + 출처 링크는 이 틀에 들어가고 **전문 복제는 벗어난다**. 한국은 일본
(제30조의4)이나 EU 와 달리 **TDM 일반 면책이 아직 없어서** "분석 목적"이 자동 방패가 되지
않는다. 그리고 저작권과 **별개 축으로 개인정보보호법**이 걸린다 — 계정명·닉네임·작성 이력이
결합되면 개인정보다.

## 결정

"원문 미재배포"를 폐기하지 않는다. **행위별로 다시 긋는다.**

1. **수집·저장 — 허용.** 원문 본문·제목·작성자·작성일·반응수를 `reviews` 에 저장한다.
   단 **DB 안에만** 둔다. 수집물은 git 에 커밋하지 않는다(마켓 로고는 ADR-0010 의 별도 근거).
2. **처리 — 무제한 허용.** 추출·요약·임베딩에 원문 전문을 쓴다. 공표가 아니다.
3. **표시 — 발췌 + 링크.** 화면에 내려보내는 본문은 **서버에서 자른 발췌**다.
   ⚠️ CSS `line-clamp` 로 접는 건 발췌가 **아니다** — 전문이 이미 브라우저에 전달된 상태라
   법적으로 전문 표시와 같다. 자르는 주체는 반드시 API 다.
   페이지 내 "더보기"로 전문을 펼치지 않는다. 더보기는 **원문 링크로 보낸다**.
4. **링크백 — 항상.** 식별자가 없으면 링크 없이 텍스트만 (ADR-0009 그대로).
5. **공개 전환 시 축소 경로를 코드에 남긴다.** 현재는 비공개 데모 전제다. 공개로 바뀌면
   발췌 길이를 줄이거나 스니펫으로 되돌릴 수 있어야 하며, 그 스위치는 **정책층 한 곳**에 둔다
   — 화면마다 흩어지면 공개 시점에 빠뜨린다.
6. **식별자는 여전히 주소만.** `source_ref` 에 본문이 섞이면 안 된다.
   `eval/test_source_links.py::test_source_ref_stores_addresses_only` 는 **그대로 유효하며 유지**한다.

## 결과

**좋은 것**
- 가장 안전한 행위(처리)에 걸려 있던 족쇄가 풀린다. 요약 품질에 원문 전량을 쓸 수 있다.
- ADR-0010 의 논증이 깔끔해진다. 마켓 로고가 "무재배포의 **유일한 예외**"라는 어색한 구조였는데,
  새 틀에서는 예외가 아니라 **같은 원칙의 한 사례**(저장은 허용, 표시는 링크백 동반)다.
- 위험이 실제로 몰리는 지점(전문 공개 표시)에 규칙이 집중된다.

**나쁜 것 (정직하게)**
- **재수집이 필요하다.** 기존 행에는 본문이 없다 — 규칙이 스키마에서 버렸기 때문이다.
  다만 추출 결과(`attributes`·`evidence`·임베딩)는 안 변하므로 `post_id` 로 기존 행을 찾아
  **새 컬럼만 backfill** 하면 LLM 재추출 비용은 들지 않는다. 전체 재색인으로 가면 든다.
- **ADR-0011 의 결정 하나를 뒤집는다.** 거기서 "디자인의 '캡션 그대로'는 의도적으로 채택하지
  않았다"고 못박았는데, 이제 발췌 형태로 채택한다. 전문이 아니라 발췌라는 점에서 완전한
  번복은 아니지만, 번복인 건 맞다.
- **개인정보 축이 새로 열린다.** 계정명·닉네임 표시 여부는 이 ADR 이 정하지 않는다 —
  **미결**로 남긴다. 저장은 위 1항으로 허용되지만 표시는 별도 판단이다.
- 비공개 전제에 기댄 결정이라, 공개 전환은 **결정 5의 스위치를 실제로 당기는 작업**을
  수반한다. 미루면 그때 잊는다.

## 대안 (기각)

- **규칙 전면 삭제** — 사용자가 처음 제안했으나 기각. 위험이 실재하는 지점(전문 공개 표시)까지
  같이 열리고, `README.md` 가 원칙으로 광고하던 것을 코드만 바꿔 무력화하면 문서와 코드가
  어긋난다. 포트폴리오 산출물로서 더 나쁘다.
- **"요약 생성에만 적용"** — 사용자의 2차 제안. 위험 축이 거꾸로다. 요약 생성이 가장 안전한
  행위이고 표시가 가장 위험하다. 기각.
- **현행 유지(스니펫만)** — 화면이 요구하는 것을 못 준다. 기각.
